## 定位与路径基准 ⭐

- **C# 参考代码是 git submodule**（2026-10-01 起）：checkout 根 = **`FEBuilderGBA/`**，
  源码目录 = **`FEBuilderGBA/FEBuilderGBA/`**（768 个 `.cs` 平铺），构建产物 + `config/data` 在
  **`FEBuilderGBA/FEBuilderGBA/bin/Debug/`**。**名字重复两层不是笔误。**
  ⚠️ **旧日志/旧文档里的 `FEBuilderGBA/xxx` 都少了一层** —— 见到自己补。
- **C# 是只读参考**（ROM 布局的权威规格），不是要开发的项目。产出在仓库根：**`cli/`**（TS，
  `node src/index.ts <cmd>` → JSON）+ **`mgba/`**（凹点助手）。
- 目标 ROM：FE8U hack「DoF」`fixtures/dream-of-five.gba`。**游戏代码 `BE8E01`，标题字段被改成了
  FE7U 的 `FIREEMBLEM2E` —— 以游戏代码为准。** 未支持 FE7J/FE8J/FE6J（SJIS）。

## ⚠️ 四条最贵的教训

**① `config/data` 在 `bin/Debug`，不在源码树。** 上游 422 文件在 `.../bin/Debug/config/data/`；
源码树 `.../config/data/` **不存在**；`cli/data/` 是 vendored 副本（27 文件）。
**下「某数据不可得」的结论前，先 `find . -name '<文件名>'`。**

**② 别把「参考代码里没有这段计算」当成「数据不在 ROM 里」。** 它是**编辑器**不是模拟器，从不算
战斗结果。正确问法是「有没有一个 `Form` 在读这个字段」。出场时间 / 职业特性位 / 地形名 / 支援
CBA 门槛 —— 全都在某个 `Form` 里读着。

**③ 值看起来像脏数据时，先怀疑自己漏了一层变换**（×2 / ÷2 / 有符号 / 单位 / 累计 vs 增量）。
正确动作是**反汇编 ROM 自己的代码**（`asmmap_FE8.txt` = 原版函数名→地址，hack 通常保留布局）。
本机 `objdump` 不支持裸二进制 → 项目级 skill 的 `scripts/disasm.py`（capstone）；它遇一条解不出的
指令就静默停止，跨数据洞要自己设 `md.skipdata = True`。
⚠️⚠️ **看到 `bl <addr>` 必须去 `asmmap` 查那个地址是什么，不能凭形状猜。** 我把一个 `bl` 当成
普通除法 helper，得出「不烧随机数」这个**完全相反**的结论并写进了报告；它其实是 `NextRN_N`。
**猜错的代价是整份报告的性质变了。**

**④ ⭐ 找地址的捷径：`patch2/` 里的 `#ENGINE` 补丁直接写出「要改哪条指令」。**
`ADDRESS=` 是**文件偏移**，`OFF:`/`FIX:` 是**改前/改后的原始字节** —— 拿 OFF 去 ROM 核对，
一致就说明指令还在原地，**不用翻符号表也能定位**。**想找「某机制在哪」先 `ls patch2/FE8U/`。**

## ⭐ 事件脚本解析的坑（已修，别再犯）

- **不能按 `\t` 切 info 列** —— 会丢掉描述里内嵌的 `[TERM]`/`[MAPTERM]`，遍历器认不出终止指令、
  一路读过头（症状：LOAD 条数暴涨 + 金币虚高）。正确做法 = `EventScript.SplitInfo`。
- **`category` 在 `sp[2..]` 里，不在 info 列**。读错列 → `{ITEM}`/`{GOLD}` 检测永不成立。
- `innerFailure`：参考实现会在子事件非正常结束时**中断调用者**；本 hack 几乎每个子事件都以
  unknown 收尾 → 需要 `{ innerFailure: 'continue' }`。
- **脚本里有分支**（`400A0000 <ptr>`）→ 遍历器逐段收集，**「段数」是上界**，不等于到手件数。

## ⭐ 经济（2026-10-01）

产物 `cli/scripts/economy-plan.ts` → `cli/out/dream-of-five.economy-{A,B}.md`。纯分析层。

- **物品单价是 u16**（`+26`，不是 u8；普通武器高字节为 0，用 u8 碰巧对）。总价 = 耐久 × 单价，
  卖价 = 总价 ÷ 2。**金币指令**：`40050300…21370000` = 入手 / `…22370000` = 失去；复合形态在
  **偏移 8** 内嵌金额 → 反汇编只返回一条复合指令，**必须按字节扫**（全 ROM 仅 4 条 + 4 个金箱）。
- **宝箱/村庄/门/制圧点/商店是同一个 12 字节 `CONDTYPE.OBJECT` 记录**（挂条件表 slot 2）。⭐
  **字段名/取值别去猜** —— 控件名就是答案（表见 docs `§3.11.8`）。
- **消耗模型必须按 `deploySlots` 算，不能按全名单算**（按 52 人算是「26 万金」这种没用的数字；
  按 `deploySlots` 算是 4 万，才和 4 万现金对得上）。
- **非主线图判据（可复用）**：`startEvent < 0x1000000` = 原版 FE8U 数据区 = 遗留槽位；本 hack 新写的
  事件脚本**全部**在 `0x1000000` 以上。遭遇图 = 标题字面 `@001F`。**合并「同一张图的多个槽位」的
  签名只能用 `startEvent|condTableAddress`**（带 `titleTextId` 就合并不了）。
- **性价比表里「有标价」≠「买得到」**：109 件里 29 件本路线商店买不到。要标 `†`。
- ⭐ **重量/追击已进模型**（docs `§3.18`）：`攻速 = 速度 − max(0, 重量 − 体格)`（只有超出的部分扣），
  追击 `|攻速差| ≥ 4`（**双向**）= **直接多打一次**（不是 +50%）。**体格不随等级涨**；**体格大 ≠
  带得动**（上限随**敌攻速**变）。敌人和自军走**同一个公式**，缺的只是**输入**。排序键 = `期望/金
  × 平均出手次数`，采购清单用**各阶段自己的速度**。⚠️ E 级铁系在**每个阶段**都最优 → **早期省的
  不是武器钱，是追击**；次一档 30/31 行都有人会掉追击 → **不能整队统一配**。
- ⭐ **特效成立时武器威力 ×3**（判据 `IsSlayerApplied`）。**性价比表不建模特效** → 「特效系排名低」
  是假象；但即使 ×3 也仍低于钢枪 → 关键不是「效率」而是「够不够」：敌人防御一高，便宜武器就是
  0 伤害，`期望/金` 失效。**性价比表只管「日常批量采购」，特效系/银系必须看具体地图。**

## ⭐ FE8 没有敌人表 —— 敌人在同一个配置记录里（2026-10-01）

**「定位敌人摆放表」的答案是：这张表不存在。** 完整版见 docs `§3.19`。

- **玩家/友军/敌人共用同一种 20 字节记录**（FE6/FE7 是 16）。**是不是敌人 = 记录自己 `+3` 的
  bits 1–2**（0 自军 / 1 友军 / 2 敌军 / 3 消灭），`bit0` = 自动升级开关，`bits3-7` = 等级。
  ⭐ 判据来源：`InputFormRef.cs` 的 `linktype == "UNITGROW"` 分支逐字节读改写。
  **别去猜字段名，控件名就是答案。** ⚠️ **`+3` 是 u8 不是 u16**（`+4` 就是坐标）。
- **记录块由事件脚本引用**（没有别的入口）：LOAD1（`402C0100`/`402C0000`，招募**和**初始敌人）、
  LOAD2/LOAD3、増援等。**常规章节的初始敌人在 `START_EVENT`（槽 18）**，增援在 `TURN`（槽 0）/
  `ALWAYS`（槽 3）。⚠️ **`GetChapterEnemyUnitDefinitions` 不是「常规章节敌人表」** —— 它只读
  槽 15/16/17 = **`FREEMAP_ENEMY_UNIT`**（魔物图用）；常规章节读 `GetChapterAllyUnitDataPointer`。
- ⭐ **「ユニット配置」表单只列脚本引用的块** → 它**不是**「玩家初始配置」的入口。普查工具
  `cli/scripts/unit-placement-census.ts`（DoF：502 块 / 2723 条敌人）。
- ⚠️ **两个真发现，别去"修"**：① `mapIndex 22`（C10B）是全 ROM 唯一 `槽11 ≠ 槽10` 的章节，槽 11
  是 9 条全友軍，而 `GetChapterAllyUnitCount` **不过滤阵营** → hard 出击位**真的是 9**。
  ② 11 个章节填了槽 12–17（魔物遭遇用），**不是章节初始敌人**。
- ⚠️ **做「某形态没被使用」这类结论时，扫描必须加「参数是合法 GBA 指针」约束**，否则 4 字节
  字面量会撞出几百个假阳性。

## ⭐ 敌人属性可以算了 —— 攻速投影（2026-10-01）

**产物**：CLI 命令 **`enemy-stats`**（`cli/src/analysis/enemyStats.ts`）。经济报告的
`ENEMY_AS = 10` 常数**已删除**（docs `§3.20`）。

- ⭐⭐ **自动升级的总开关是 `+3` bit 0，而且它在阵营判断之前。** **DoF 有 11%（303/2805）的敌人
  记录是 0** → 漏掉会把它们的属性算高。
- ⭐⭐ **`unit[+0]` = pCharacter、`unit[+4]` = pClass。顺序反了会读错成长率表。**
  证据：`AutolevelRealistic` 把 `unit[0]->+0x0B` 当「角色表初始等级」，
  `IncreaseUnitStatsByLevelCount` 把 `unit[4]->+0x1B` 当成长率。**所以敌人用职业成长率。**
- **两条路径**：`(角色.flags|职业.flags) & 0x80` 置位 → `AutolevelRealistic`；否则角色 id > 0x40 →
  `AutolevelUnit`；否则 `AutolevelRealistic`。DoF 实测 **2458 / 44 / 303（无）**。
  ⚠️ 两条都烧 RNG（`NextRN_N` / `Roll1RN`）→ 基准 = `成长 × 等级 / 100`，**随机成分 ±1 点**
  → **要给区间不给点值**。
- ⚠️ **转职那一轮的掩码是 `0x100`**，即 `(角色.abilityFlags[1] | 职业.abilityFlags[1]) & 0x01`
  = 特性2 bit0「上級クラス」。**是 `& 0x01`、而且角色与职业要 OR 进来** —— 我原先记成 `& 0x02`、
  只取职业，都是错的。加成值：hard 19 / 普通 9。
- ⚠️ **`IncreaseUnitStatsByLevelCount` 的那个 id 参数根本没被读** —— 成长率永远来自 `unit[+4]`。
- ⭐ **攻速可以是负数，不是 bug**（引擎从有符号字节里减惩罚、不钳零，74/2805 条为负）。
- ⚠️ **`classId == 0` 表示「用角色自己的职业」，不是「职业 0」。** 探针里写错过一次。
- ⚠️ **按章去重 vs 全 ROM 去重，两个数都对**（2805 vs 2723，两张图共享配置块）。**别当成矛盾。**

## ⭐ DoF 是分线游戏

分线前 `mapIndex` 0–8（21 人）｜A 线 9–17（9 人）｜分线点 18｜B 线 19–27（12 人）｜合流 36–50（16 人）。

- **分组必须用 `mapIndex`，不能用 `chapterNumber`**（C6x / C7A / C7B 章号都是 7）。
- 96 条支援边 **0 条跨线** → **支援规划必须先定线**；B 线没有开局支援。
- 可玩名单三口径：255 槽 → **62** 有支援数据 → **61** 有实际伙伴 → 剔除 **Rophon(#38)**。
- **`classes.json` 的对象 key 不是 class id** → 要 `Object.values(C).find(c => c.id === classId)`。
  **转职可从 `caps` 反推**（未转职 `str/skl/spd/def` 上限一律 20，转职 ≥25）。
- 编队 `deploySlots` = 初始配置块条数；未用槽位是模板填的 → **数条数对，数名字会数出十几个同一角色**。
- **写校验脚本先确认字段真的存在** —— 曾用不存在的 `name` 过滤，集合恒为空、检查恒通过
  （79/79 全过）。**「全过」可能只是空集。**

## 杂项（详细版见 docs）

- `RomInfo.*_pointer` 是**指针槽**偏移，表地址 = `p32(slot)`（u32 落在 `[0x08000000,0x0A000000)`
  就减 `0x08000000`）；`_address` 结尾的才是直接偏移。⚠️ 指针槽可以在**代码段**里。
- 控件名 = `<B|W|D|P><字节偏移>`，旁边 Label 的 Text 是字段名 —— 还原结构体最快。
  **表的读入规则逐字照抄 `Init()`**（定长 vs 扫终止符）；定长表读满会静默污染 ID→名字 映射。
- 角色表 `+12..+19` 是**相对职业基础值的有符号增量**（必须 `rom.i8()`）；**增量为 0 是最常见的值**。
- **跟本仓库相关的 skill 一律放项目级** `<仓库根>/.workbuddy-ai/skills/`（用户明确要求）；
  ⚠️ 项目级 skill **不在启动索引里** → `Skill` 工具会失败，直接 `Read` SKILL.md。
- 参考程序仅 Windows 可构建；`cli/out/` 是生成物（已 `.gitignore`）。单位名过 `displayName()`
  （剥 `@XXXX`）；**章节标题不能剥** —— 地图标题分类依赖字面 `@001F`。
- RNG/凹点规则见 docs `§3.15` + `§3.17`；产物 `mgba/fe-aodian.lua` + `mgba/test/`（自测 124 项）。
- ⚠️ **凹点助手是只读面板、没有热键**（2026-10-01 按用户要求删掉整套 `L+…`/`R+…`，与游戏按键
  冲突）→ **别再往面板加按键**。⚠️ **面板闪烁 = 每帧无条件重画**：「内容不变就别碰缓冲」
  （`CONFIG.RENDER_DIFF`）；异常同理，判据必须是「消息变了才再报」，**不能是「成功后复位」**。
- **凹点 = 打敌人 → 长经验 → 升级** → 预测必须先把「这一仗消耗几个随机数」算进去。
  ⭐ `Roll1RN`/`Roll2RN` **概率 0 也照烧 1/2 个**；`gBattleStats` 低位 **1=真实战斗（已在烧）/
  2=模拟预览（一个没烧）** → **预览界面就是预测点**（面板要用**最终**命中/必杀，不是基础值）。
