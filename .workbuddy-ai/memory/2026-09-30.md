## ⭐ 新解出的表：强制出击（強制出撃）

参考程序有编辑器 `EventForceSortieForm`（提示语「必ず出撃しなければいけないユニットを設定します」），
指针槽 `ROMFE8U.cs:95` → **`0x8483C`**；本 ROM 解引用后表在 **`0x1C099D0`**。

**`Init()` 只暴露两个字段**（`u16(+0)` 和 `u8(+3)`）—— 中间那个字节必须反汇编。
`IsCharacterForceDeployed`(`0x080953F0`) 尾调用 **`IsCharacterForceDeployed_`(`0x08084800`)**：

```
+0  u16 unitId     （0xFFFF = 表尾）
+2  u8  route      （0xFF = 不限，否则比 ChapterData+0x1B）
+3  u8  mapId      （0xFF = 不限，否则比 ChapterData+0x0E，值是地图设置索引）
循环步进 adds r2,#4；三个条件全中 = 必上
```

**实测 28 条 × 4 字节、13 个唯一单位：**

| 角色 | 章数 | 哪几章 |
|---|---|---|
| **Rena** | **45（全部）** | 全程（2 条 `map=0xFF`） |
| **Arcus** | 8 | A 线中段 7 章 + C25 |
| **se'Mori** | 7 | B 线中段全部 |
| Garath | 2 | C6x, C8x |
| Marie / Meliza / Eudira / vi'Shen / Severin / Stolypin / Annelise / Thyra / Sheila | 各 1 | 单关点名 |

### ⚠️ `route` 字节静态判不了（如实说明，别二选一）

它比的是 **RAM 里的** `ChapterData+0x1B`。原版取值已钉死：
`0x01`=序盤（初值）、`0x02`=E編（`Command_EirikaMode` @`0x08086564`）、
`0x03`=F編（`Command_EphraimMode` @`0x08086580`）。
两个函数各只有一处引用，都在 `0x9F3634` 的分线选单表里（`MenuCommand_DrawRouteSplit`）。

**本 ROM 28 条里 14 条带 route 过滤，其中 12 条是 `0x01`，而它们指向的地图横跨
分线前 / A 线 / B 线 / 合流后** → 要么该字节惰性，要么那些记录根本不生效。
**两种读法都成立，静态分辨不了。** CLI 的做法：不过滤、原样输出 `routeFilter`、
写进 `limitations`；报告里给出「两种读法最多差 2 个必上单位」。

## 编队人数（部署槽位）不需要新表

`deploySlots` = 初始配置块（condition slot 10）的**记录条数** ——
游戏自己的 `GetChapterAllyUnitCount`(`0x08012344`) 就是数它。slot 11 = 困难模式。

**45 张单周目剧情图：中位数 12 格、最多 18（C20/C25）、最少 1，合计 522 格。**

- **C6x（索引 8）是 3 格 3 必上 → 0 自由位**
- **Postscript / C23x 只有 1 格**（单人剧情图；C23x 是 Kai/Claudiya 加入关）
- 分线前每章只有 3–12 格 → **21 人里必须主动放弃一半**
- **自由位 = 槽位 − 必上**；终盘 16–18 格 vs 46–49 人 → 最终阵容只有名单的 1/3

### ⚠️ 槽位是模板填的，别按名字去重（新的第 4 条陷阱）

未使用的槽位**不是空的**，而是填了「同一个 `unitId` + 当章 `classId`」的模板记录：
本 ROM **683 条配置记录里 534 条**是这种填充（C1 = `unit 2 / Thief` ×6、
C11A = `unit 2 / class 9` ×12、C20 = `unit 2 / class 53` ×16）。
**数条数 = 出击位数（对）；数名字 = 数出 12 个同一角色（错）。**

### 交叉验证（已进 `validate`）

**每条指名某张图的强制出击记录，其单位都出现在那张图的配置块里 —— 26 条里 24 条命中。**
例外是 C15 的 Severin / Stolypin（靠开场事件入场，不预置）。
这条同时验证了两张表的偏移都对。

> ⚠️ 曾写过一个**假验证**：用 `p.name` 过滤模板 → 但内部 `PlacedUnit` 根本没有 `name`
> 字段（名字是 `index.ts` 序列化时才加的），于是 `named` 恒为空、检查恒通过（79/79）。
> **教训：校验脚本先确认字段真的存在**，否则「全过」可能只是空集。
